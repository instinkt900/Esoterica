### 2026-08-25 — Defer the External.zip download until Phase 2
**Context:** the plan flagged the External.zip (~283 MiB) download as Phase 0's first open
item — the LLVM version the Reflector needs is baked into the zip, not into `LLVM.props`
(see [03-Dependencies.md](03-Dependencies.md)).
**Decision:** do not download it during Phase 0. Pin LLVM and fetch it in Phase 2, when the
compiler toolchain is actually being built.
**Rationale:** Phase 0 needs only the host toolchain (clang 19.1.1 and gcc are already
installed on the development machine); the download is large, and the version choice belongs
with the Phase 2 task that must build against it.
**Alternatives rejected:** downloading it now — weeks of unused disk, and it would pre-empt
the Phase 2 investigation that the pinning decision depends on.

Noted during the initial survey, in `Code/Scripts/NinjaGen/NinjaGen.py` (the stale build script
this port rewrites, so these get fixed as a side effect rather than as upstream fixes):

- Declares `-std=c++17` while the project requires C++20.

Also noted, not fixed:

- `Code/Applications/BuildGenerator/` is non-functional (emits rule references with no rule
  definitions, and parses the legacy `.sln` GUID format). Left alone deliberately.
- `Docs/docs/CodingGuidelines.md` is referenced by `Esoterica.slnx` but absent from the
  repository.

Re-verification on 2026-08-25 (against `6813cf9`) noted, not fixed:

- **Case-sensitive-path landmines.** `Esoterica.props` imports `Code\PropertySheets\Navpower.props`
  but the file on disk is `NavPower.props` (capital P); `ResourceServerApplication.cpp:6` includes
  `"Base/Imgui/Platform/ImguiPlatform_win32.h"` but the header on disk is `ImguiPlatform_Win32.h`.
  Both compile on Windows because the filesystem and toolchain are case-insensitive. The build
  generator must resolve `.props` imports **and** `#include` paths case-insensitively.
- `Code/Base/Memory/Memory.h` lines 23–27: the non-Windows `#else` defines `EE_STACK_ALLOC` /
  `EE_STACK_ARRAY_ALLOC` as **empty macros** — a non-functional stub that breaks every call
  site on a non-Windows build. The port completes it in Phase 1 (see [TouchedFiles.md](TouchedFiles.md)).
- `Code/Base/Math/Platform/Math_Win32.h`: `GetMostSignificantBit( uint64_t )` passes its
  argument to `_BitScanReverse64` cast to `unsigned long`, silently truncating 64-bit values to
  32 bits. The Linux `__builtin_clzll` implementation will be correct for the full 64-bit range;
  that is a deliberate behaviour fix, and it is recorded here rather than hidden.

During P0.1 (2026-08-25), the generator's case-insensitive file resolution surfaced the
following; recorded so the Phase 1 worklist is complete:

- **More case-sensitivity landmines (project file-list entries vs disk).**
  `NavPower.cpp` / `Navpower.cpp` (`Code/Engine/Navmesh/`); `enkits/` entries vs the
  `EnkiTS/` directory on disk (four files under `Code/Base/ThirdParty/`);
  `Resources/Resource.h` / `resource.h` (Reflector and BuildGenerator). The generator
  resolves all of these case-insensitively with warnings, so they block nothing; they
  remain upstream defects worth an issue report.
- `Code/Base/Utils/GlobalRegistryBase.h:2` — `#include "Base\Esoterica.h"` with a literal
  backslash. Compiles on Windows (case-insensitive paths), fatal on Linux, and it is in the
  include chain of every file that pulls in `Memory.h`. **Not in the
  [TouchedFiles.md](TouchedFiles.md) registry** — if Phase 1 edits this file it must be
  registered first (AGENTS.md escalate rule).
- `Code/Base/Esoterica.h:73`–74 — uses `va_list` without including `<stdarg.h>`; MSVC
  headers provide it transitively, clang does not. The file is already registered for the
  platform `#elif` at line 55; the missing include would ride along with that edit.
