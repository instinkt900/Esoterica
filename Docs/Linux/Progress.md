### 2026-08-27 - The parser lives in its own file, not in `NinjaGen.py`

**Context:** `NinjaGen.py` is the one upstream file this port rewrites wholesale, so its merge
handling is a special case ([01-UpstreamMerges.md](01-UpstreamMerges.md)).
**Decision:** Put solution and project parsing in a new `Code/Scripts/NinjaGen/ProjectParser.py`.
`NinjaGen.py` keeps only flag translation and ninja emission.
**Rationale:** A new file cannot conflict with upstream at all. The less of this work that sits
inside `NinjaGen.py`, the smaller the one file with real merge risk. It also makes the parsing
testable on its own.
**Alternatives rejected:** One large `NinjaGen.py`, which is what the stale script does. It puts
every line of the generator into the only file that can conflict.

### 2026-08-27 - The generator resolves path case, rather than upstream fixing the names

**Context:** Eight `.vcxproj` entries disagree with the case of the file on disk. MSBuild does not
care. Linux does.
**Decision:** `resolve_file_ignoring_case()` matches the entry to the real file and warns.
**Rationale:** Conventions rule 3 forbids fixing upstream files that the task does not need, and
rule 5 says to fix a vendored-code problem in the build generator. This is the same shape of
problem. It also keeps working when upstream adds the next mismatch.
**Alternatives rejected:** Editing the `.vcxproj` files, which
[TouchedFiles.md](TouchedFiles.md) rules out. Failing the build, which blocks on a problem that
does not affect Windows and that upstream has no reason to fix.

### 2026-08-27 - Console platform tokens warn instead of being dropped as Windows

**Context:** `_Durango` and `_Scarlett` name Windows-derived console platforms.
**Decision:** `PLATFORM_TOKENS` classes them as `other`, which warns, not as `windows`, which is
silent.
**Rationale:** Phase 0 names a silently dropped source as the failure mode that hurts most on a
future upstream merge. Only `_Win32`, `_Win64` and `_Windows` drop quietly.
**Alternatives rejected:** Treating every Windows-family token as `windows`. It is tidier and it
hides exactly the drift this rule exists to catch.
