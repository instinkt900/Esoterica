# Upstream sources the Linux build drops.
#
# Hand-maintained. One glob or path per line, matched against the repo-relative path.
# '#' starts a comment.
#
#   **/     zero or more leading directories
#   **      anything, including '/'
#   *       anything except '/'
#
# A pattern that matches nothing is reported as a problem, because it is usually a leftover
# from an upstream rename. Keep this file honest: every line here should be doing work.
#
# Say *why* a file is excluded. The next person to read an upstream merge diff needs it.

#-------------------------------------------------------------------------
# Windows platform implementations
#-------------------------------------------------------------------------

# Upstream puts platform code in <System>/Platform/<System>_Win32.cpp. Each of these gets a
# _Linux sibling, listed in LinuxSources.txt. See Docs/Linux/00-Conventions.md rule 1.
**/*_Win32.cpp

# Application entry points live in a Win32/ directory rather than taking a suffix. The glob
# above already covers today's files; this one catches an unsuffixed file added to those
# directories later.
**/Win32/**

# Windows implementations that carry no suffix at all. Same rule as the two globs above - the
# file is a Windows implementation and its _Linux sibling is listed in LinuxSources.txt - but
# the name gives the generator nothing to match on, so each one needs a line of its own.

# 552 lines of COM IFileDialog. The shared header is SystemDialogs.h, which both sides include;
# excluding the .cpp drops only the Windows implementation. Sibling: SystemDialogs_Linux.cpp.
Code/EngineTools/Core/SystemDialogs.cpp

# ReadDirectoryChangesW. Upstream already guards the namespace body with #if _WIN32, but the
# <windows.h> include above it is unguarded, so the file still has to be dropped rather than
# left to compile to nothing. Sibling: FileSystemWatcher_Linux.cpp, on inotify.
Code/EngineTools/FileSystem/FileSystemWatcher.cpp

# The Resource Server entry point: _tWinMain, a NOTIFYICONDATA system tray icon, an ITaskbarList3
# progress overlay, and a named single-instance mutex. Its header includes <shellapi.h> and
# Application_Win32.h, and only this .cpp includes that header, so dropping the .cpp drops both.
# Sibling: Linux/ResourceServerApplication_Linux.cpp. See P7.3.
Code/Applications/ResourceServer/ResourceServerApplication.cpp

#-------------------------------------------------------------------------
# Direct3D 12
#-------------------------------------------------------------------------

# The whole Direct3D 12 backend, 6084 lines. It carries no platform suffix and no #if _WIN32
# guard, so nothing but this line keeps it out of a Linux build. RHI.h is API-agnostic, so the
# Vulkan backend is a sibling file rather than a change to the interface.
# Phase 5 adds it. See Docs/Linux/Phases/Phase5-VulkanRHI.md.
Code/Base/Render/RHI_Direct3D12.cpp

# AMD's Direct3D 12 memory allocator, vendored by upstream. The Vulkan equivalent is VMA, which
# arrives as an External/ dependency in Phase 5 rather than a vendored source.
Code/Base/ThirdParty/D3D12MemoryAllocator/**


#-------------------------------------------------------------------------
# Windows-only build tooling
#-------------------------------------------------------------------------

# BuildGeneratorApplication.cpp parses Esoterica.slnx and writes the per-module reflection file
# lists that MSBuild consumes. It is the MSBuild half of the build system, and NinjaGen.py does
# the same job here from the three source lists. Its only actual compile error is __debugbreak,
# so a shim would make it build - but building a .sln parser on a platform with no .sln is
# pointless, and the shim would be the first of many.
Code/Applications/BuildGenerator/**


#-------------------------------------------------------------------------
# Upstream code with no callers, that does not compile
#-------------------------------------------------------------------------

# The FFX parallel sort driver. It has no callers anywhere in Code/ - upstream removed radix
# sorting from the culling pipeline in 47e6293 and left the file in the .vcxproj.
#
# It includes the generated reflection headers for the seven Render/Shaders/FFX/*.esf shaders,
# and those shaders do not compile: each one redefines RWStructuredBuffer to RWBuffer before
# including FFX_ParallelSort.esh, which makes the RWStructuredBuffer<FFX_ParallelSortCB>
# parameter at line 475 a typed buffer of a struct. DXC 1.10 rejects it for DXIL and SPIR-V
# alike, so this is upstream's bug and not a Linux one. The shaders are skipped by the matching
# list in Reflector.cpp; this line drops the C++ that would otherwise fail to find their headers.
#
# Reported upstream rather than fixed - Conventions rule 3. Remove both entries when upstream
# fixes the shaders or deletes the file.
Code/Engine/Render/Device/DeviceRadixSort.cpp
